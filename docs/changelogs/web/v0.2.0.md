# Web app — JADE LENS v0.2.0

## Index-driven navigation

- The file tree is now built from `Index.json` rather than the raw git tree: only
  primary (indexed) files are listed, and `Index.json` itself is excluded. When
  `Index.json` is absent the tree is empty — there's no fallback to the git tree.
- The old pinned, emphasised `Index.json` entry at the top of the tree is gone.
- Each file entry shows its `Scope` description — as a tooltip on hover (desktop)
  and in a bottom sheet on long-press (mobile).

## Sidecars in the card view

- A JSON field whose value is a sidecar wikilink renders as a **truncated preview**
  (one rendered line, at most 100 characters, cut on inline-span boundaries so
  styling is never broken mid-token) instead of the raw wikilink.
- A ↗ icon on the preview navigates to the full sidecar file; navigating back
  restores the parent file's scroll position.
- When viewing a sidecar, the top bar shows its **logical location**
  (e.g. `Projects / Garden[comparisons/0/description]`) rather than the on-disk
  `.sidecars/` path. Sidecar files never appear in the file tree — they aren't
  indexed.

## Data-format version awareness

- The app checks `.jade/version` against the data format it supports. On a
  mismatch it switches to **read-only** and warns: older data → migrate with the
  CLI/skill; newer data → reload (and clear the cache if needed). A final guard in
  the commit path blocks edits from being written against a version-mismatched
  repo.

## Under the hood

- The web mutation pipeline gains all of the v2 pipeline behavior — `create_file`
  indexing, end-of-apply enforcement, and sidecar promotion/propagation — kept
  byte-identical to the Python CLI by the shared conformance suite.
- New developer-only end-to-end harness support: a dev-seed that pre-fills
  Settings from `.env.local`, and an `npm run dev:e2e` script that opens the app in
  a private window. Both are dead code in production builds.
