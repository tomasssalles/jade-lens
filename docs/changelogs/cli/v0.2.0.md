# CLI and skill — JADE LENS v0.2.0

The themes of this release: **sidecar promotion** for long text values,
**end-of-apply enforcement** of the data-format invariants, and the
**versioning + migration** machinery — a real `jadelens update`, an automatic
post-update sync, and the first bot-driven data migration (`v1 → v2`).

## New `jadelens` subcommands

- `jadelens update` — update JADE LENS itself: reinstalls the `jadelens` package
  from the `cli-latest` tag, then runs `post-update` to bring your data repos in
  sync. A deliberately thin shell-out, nothing more.
- `jadelens post-update [--data-repo <path>]` — rewrite a data repo's scaffolded
  files (session-start hook, `.claude/settings.json`, `CLAUDE.md`,
  `.jade/config.json`) to match the installed CLI, commit, push, and re-render the
  skills. With `--data-repo` it updates one repo; with no argument it scans
  `~/.claude/skills/` and updates every JADE LENS repo it finds. Idempotent — a
  no-op when the repo's skill marker already matches the installed version.
- `jadelens migrate <data-repo> [--finalize=vN-v(N+1)]` — drive a data-format
  migration as a one-step-at-a-time state machine: tag a checkpoint, print the
  runbook for the bot to follow, then (on `--finalize`) bump `.jade/version`, tag
  the end, and push. Prints `DONE` once the data reaches the version this CLI
  supports.
- `jadelens check <data-repo>` — run the full end-of-apply enforcement pass on its
  own (no operations, no commit). Used as the final integrity gate of a migration.
- `jadelens run-migration-helper <data-repo> <id>` — invoke a named Python
  migration helper (e.g. `v1_v2/promote-sidecars`), reading its JSON input from
  stdin.

## Safer applies: version guards and `--unsafe`

- `jadelens apply` now checks the **data-format version** (`.jade/version`) before
  doing anything: it aborts with a clear message if the data is older than this
  CLI supports (run the migrate skill) or newer (run `jadelens update`).
- It also checks the **skill's CLI-version marker** against the installed CLI and
  aborts if they disagree, pointing you at `jadelens update` or
  `jadelens post-update` as appropriate.
- New `apply --unsafe` flag, for migrations only: skips the version check and the
  end-of-apply enforcement, pulls but does not push (leaving that to
  `jadelens migrate`), and prints a visible ⚠️ warning. Only the migration runbook
  should ever use it.

## Mutation pipeline (mirrored byte-for-byte in the web app)

- **`create_file` indexing.** New optional `indexed` (default `true`) and `scope`
  fields. Signal intent with a single field: pass a non-empty `scope` to create a
  primary file, or `indexed: false` for a non-primary file (scope defaults to
  null). Omitting both is rejected. When indexed, the runtime appends the
  `{"File": "[[path]]", "Scope": …}` entry to `Index.json` as part of the same
  atomic batch — the bot never adds index entries by hand.
- **End-of-apply enforcement.** Every successful batch is checked against the
  data-format invariants: `Index.json` shape, no duplicate `File`, every primary
  file indexed; no file-stem / directory-name collision in a parent; every
  wikilink resolves to an existing file; and the sidecar structural rules. (The
  old `delete_path` dangling-reference check is now subsumed by the wikilink
  integrity scan.)
- **Sidecar promotion.** A JSON string value containing more than one CommonMark
  block is automatically promoted to a standalone `<stem>.sidecars/<pointer>.md`
  file, with the field value replaced by a wikilink. `jadelens apply` reports
  every sidecar it created so the bot knows what the runtime did.
- **Sidecar propagation.** Renaming or deleting a `.json` file moves or deletes its
  `.sidecars/` subtree; `json_patch` `move` / `remove` ops carry their sidecars
  along or delete them.

## The skill

- **Single template.** The skill is rendered from one bundled `skill.md` (plus a
  `migrate-skill.md`) instead of versioned `v<X.Y.Z>.md` templates. The rendered
  marker now records the **CLI version** (`cli-version=…`), which the apply guard
  and `post-update` use to detect staleness.
- **Automatic updates.** The session-start hook now runs `jadelens post-update`, so
  a repo catches up to a newer CLI — rewritten scaffold files plus re-rendered
  skills — on the next session, with no manual step.
- **New `/<assistant>-migrate` skill.** Rendered and symlinked alongside the main
  skill; it runs the migrate loop (call `jadelens migrate`, follow the runbook,
  `--finalize`, repeat until `DONE`).
- **Sidecar + index instructions.** The skill explains what the runtime does
  automatically (promotion, index entries, sidecar propagation), what the bot may
  still do deliberately, and what it must never do (hand-create sidecars or inline
  wikilinks). The bot is also told to surface any ⚠️ warnings from `jadelens apply`
  in the chat.

## Migrations

- The first real data migration ships: **v1 → v2**. `jadelens/migrations/v1_v2/`
  contains a `RUNBOOK.md` and a `promote-sidecars` helper that batch-promotes every
  qualifying multi-block string in the repo; the bot then resolves any
  stem/directory collisions, and `jadelens check` confirms all v2 invariants before
  the migration is sealed. See `docs/changelogs/data-format/v2.md` for the format
  details.
